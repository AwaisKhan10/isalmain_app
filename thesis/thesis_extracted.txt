ABSTRACT

[43] STYLE=Normal
The "ISLAMIAN APP" is a cross-platform mobile application developed using Flutter and Firebase to address coordination challenges between teachers and students in academic institutions. Traditional methods of sharing class timetables—notice boards, WhatsApp groups, and paper schedules—are often fragmented, outdated, and lack direct communication channels between instructors and learners.

[44] STYLE=Normal
This project delivers a dual-role system: teachers can create, update, and delete class schedules filtered by department, section, and semester; students can view personalized timetables based on their academic profile and initiate real-time chat with respective teachers. The application employs Firebase Authentication for secure login, Cloud Firestore for real-time data synchronization, and the MVVM architectural pattern with Provider and GetIt for maintainable code structure.

[45] STYLE=Normal
Key features include role-based navigation, onboarding flow, profile management, online/offline status indicators, unread message counts, and deterministic chat identifiers for consistent conversation threading. The thesis documents requirement engineering, system modelling, implementation details, and comprehensive testing of authentication, scheduling, and messaging modules.

[46] STYLE=Normal
Limitations such as absence of push notifications, admin dashboard, and classroom location mapping are acknowledged. Future work may include FCM integration, administrative controls, and enhanced security policies. Through structured development and manual testing, Islamian App demonstrates a practical, scalable solution for academic scheduling and communication.

INTRODUCTION

[100] STYLE=Heading 2
1.1 Overview

[101] STYLE=Normal
The "ISLAMIAN APP" (package name: sheduling_app) is a mobile solution designed for educational institutions where teachers and students require a centralized platform for class timetable management and direct communication. Built with Flutter for cross-platform deployment and Firebase for backend services, the application supports two distinct user roles with tailored interfaces: teachers manage schedules while students consume filtered academic timetables and message instructors.

[102] STYLE=Normal
The system integrates Firebase Authentication for email/password registration and login, Cloud Firestore for persistent and real-time data storage, and Provider-based state management following the MVVM pattern. An AppGate component at startup determines routing based on authentication state, onboarding completion, and detected user role (teacher or student).

[103] STYLE=Heading 2
1.2 Motivation of the Project

[104] STYLE=Normal
Academic scheduling in many colleges still relies on informal channels. Teachers announce changes verbally or through unstructured messaging groups; students miss updates or contact the wrong faculty member. This fragmentation increases confusion, especially at semester transitions when sections and timetables change.

[105] STYLE=Normal
Mobile penetration among students and faculty makes a dedicated application a practical intervention. By combining schedule publication with in-app messaging, Islamian App reduces dependency on external platforms and keeps academic communication contextual—linked to specific courses and instructors.

[106] STYLE=Heading 2
1.3 Problem Statement and Description

[107] STYLE=Normal
There is no unified digital system in the target institutional context that simultaneously allows teachers to publish structured class schedules (department, section, semester, subject, time) and enables students to view only relevant entries while communicating with assigned teachers in real time.

[108] STYLE=Normal
Existing alternatives—paper timetables, PDF notices, and generic chat applications—lack role-based filtering, centralized updates, read receipts, and online presence indicators. Students cannot reliably determine which schedule applies to their section; teachers cannot efficiently broadcast changes to the correct audience.

[109] STYLE=Heading 2
1.4 Proposed Solution

[110] STYLE=Normal
Islamian App proposes a dual-role Flutter application with the following core capabilities:

[111] STYLE=List Bullet
Secure registration and login for teachers and students with automatic role detection.

[113] STYLE=List Bullet

[114] STYLE=List Bullet

[116] STYLE=List Bullet
Onboarding screens and welcome flow for first-time users.

[206] STYLE=Heading 2
2.5 Literature and Comparative Analysis

[207] STYLE=Normal
Several commercial and open-source systems address academic management, including Learning Management Systems (LMS) such as Moodle and Canvas. These platforms focus on course content, assignments, and grades rather than lightweight timetable broadcasting with instant messaging. WhatsApp and Telegram groups are widely used informally but lack structured schedule filtering and role-based views.

[208] STYLE=Normal
ISLAMIAN APP differentiates itself by combining schedule CRUD for teachers, automatic student filtering, and Firebase real-time chat in a single mobile binary. Compared to paper-based timetables, the app provides immediate update propagation when teachers edit entries. Compared to generic LMS modules, the interface is simplified for daily schedule consultation and quick teacher contact.

[209] STYLE=Normal
Cross-platform Flutter reduces development effort versus maintaining separate Android (Kotlin) and iOS (Swift) codebases. Firebase eliminates server provisioning costs critical for student projects while providing authentication and real-time sync comparable to custom WebSocket backends.

[210] STYLE=Normal
Moodle and Google Classroom excel at course materials but impose learning curves for simple timetable broadcasting. Dedicated timetable apps on app stores often lack institutional branding and teacher-student chat tied to schedule rows. ISLAMIAN APP occupies a niche: lightweight, role-aware, Firebase-backed.

[211] STYLE=Normal
Prior student projects at the department using Flutter-Firebase stacks informed technology selection. The Lost2Found proposal template structure was adopted for thesis formatting consistency while content was entirely rewritten for the Islamian App domain.

1.11 Background of Academic Scheduling Systems

[418] STYLE=Normal
Educational institutions worldwide rely on timetables to coordinate lectures, laboratories, and tutorials. Traditional scheduling methods include printed sheets distributed at the start of semester, notice boards outside departments, and informal WhatsApp groups managed by class representatives. While these methods are familiar, they suffer from version control problems: when a teacher reschedules a class, students may attend at the wrong time or location unless the update propagates quickly.

[419] STYLE=Normal
ISLAMIAN APP was conceived specifically for the Islamia College Peshawar context where Computer Science and allied departments run multiple sections per semester. Teachers require a lightweight tool to publish schedules without learning complex LMS modules. Students require read-only access filtered to their registered department, section, and semester so that information overload is avoided.

[420] STYLE=Normal
The integration of messaging within the same application reduces context switching. Rather than searching for a teacher's phone number after discovering a schedule conflict, the student taps the chat icon on the relevant class card and enters a conversation thread keyed to that academic relationship.

4.9 Design Rationale for Firebase Collections

[440] STYLE=Normal
Separate collections teacher_user and student_user avoid schema polymorphism complexity in a single users table while enabling role-specific fields (qualification, subjects for teachers; section, semester for students). The class_time_shedule collection name reflects legacy spelling in codebase; fields use snake_case class_section for Firestore query compatibility.

[441] STYLE=Normal
Messages are stored in a flat collection filtered by chatId rather than subcollections under each user to simplify StreamBuilder queries. Conversations duplicate summary metadata to avoid scanning all messages when rendering the inbox list—a standard denormalization pattern in NoSQL chat systems.

[444] STYLE=Normal

APPENDIX F — FIREBASE SECURITY RECOMMENDATIONS

[536] STYLE=Normal
Production deployment should apply Firestore rules allowing users to read/write only their profile document and messages where senderId or receiverId matches auth.uid. class_time_shedule writes should be restricted to authenticated teachers. Remove password field from toJson() serialization entirely.
